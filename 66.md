## Steps
1. Open the app in the browser at a viewport width of **exactly 760 px**. Example: the detail page of a recipe.
2. Look at the header buttons (delete/icon variants), the rating trigger and the PortionScaler (after #65). Open the rating.

## Expected
At 760 px the whole app consistently uses the phone layout. `useIsDesktop()` uses `(min-width: 761px)`, so 760 px counts as phone (tab bar, rating sheet).

## Actual
Tailwind v4 compiles `max-[760px]:` to `@media not all and (min-width:760px)`, which means `width < 760px`. At exactly 760 px the JS layout is phone (sheet, tab bar), but every `max-[760px]:` class still applies the desktop styles. The result is small tap targets, text labels on the header buttons and similar. Only this one pixel width is affected.

## Fix idea
Move every `max-[760px]:` to `max-[761px]:` in one go, or define a shared custom variant, e.g. `@custom-variant phone (@media (width < 761px))`, so CSS and `SHELL_DESKTOP_QUERY` are guaranteed to match.

## Screenshot
None. The analysis is based on the built CSS (`dist/assets/*.css`) and `src/hooks/useIsDesktop.ts`.

## Severity
Low. Only one exact window width is affected, and real phones (≤ 430 px) are not affected.

Found during the E2E check of PR #65 (#58). The PR mentions it as a known gap.

# Spec (Dispatcher)

## Context
Breakpoint-Lücke bei genau 760 px: max-[760px]-Klassen vs. useIsDesktop (761 px) — siehe Originalmeldung oben.

## Goal
CSS und JS teilen sich genau eine Handy/Desktop-Grenze: Handy < 761 px, Desktop ≥ 761 px.

## Behaviour
Bei genau 760 px gilt überall das Handy-Layout (Tab-Leiste, Bewertungs-Sheet, Icon-only-Kopfknöpfe, große Tippflächen). Bei 761 px gilt überall Desktop.

## Acceptance criteria
1. Es gibt eine gemeinsame Tailwind-Variante (z. B. `@custom-variant phone (@media (width < 761px))`) oder alle `max-[760px]:`-Klassen sind auf die 761-px-Grenze umgestellt; im gebauten CSS kommt keine Media-Query mehr vor, die bei 760 px Desktop-Stile anwendet.
2. `grep -rn 'max-\[760px\]' src` liefert nichts mehr (oder nur noch die neue Variante).
3. Ein Kommentar/Test verknüpft die CSS-Grenze mit `SHELL_DESKTOP_QUERY` in `src/hooks/useIsDesktop.ts`.
4. Tests, Build, Prettier grün.

## Non-goals
Keine Änderung des Breakpoint-Werts selbst; keine Layout-Änderungen über die Grenze hinaus.

## Assumptions
Gemeinsame Custom-Variante bevorzugt (eine Stelle), Name frei wählbar.

## Affected areas
alle Dateien mit `max-[760px]:` (19 Stellen in src/), `src/index.css` (bzw. Tailwind-Entry), `src/hooks/useIsDesktop.ts`.

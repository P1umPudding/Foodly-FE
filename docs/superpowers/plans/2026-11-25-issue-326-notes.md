## Assumptions (worker)

- A1 `@capacitor/browser` is pinned exactly to `8.0.5` (npm `latest`, peer `@capacitor/core >=8.0.0`); `@capacitor-community/keep-awake` exactly `8.0.1`.
- A2 Natively `supported` is always `true`, so the wake-lock toggle also shows on the recipe page (`RecipeDetail` toggle + ⋯ menu), as it does on web browsers with the API. This is intended. iOS ≥ 18.4 also uses the plugin natively.
- A3 Native lifecycle: `keepAwake()` once on switch-on, `allowSleep()` on switch-off and in cleanup (unmount / recipe switch). There is no `visibilitychange` re-acquire natively. `keepAwake.ts` serialises calls through one promise queue (like `enqueue` in `timerNotifications.ts`), so a pending `keepAwake` can never land after a later `allowSleep`.
- A4 A plugin error sets `enabled` to `false` (as today); no UI message.
- A5 `openExternal(url)` catches errors from `Browser.open` silently. The link keeps `href`, `target="_blank"`, `rel`; only an `onClick` (with `preventDefault`) is added natively. URLs are always absolute http(s) (`isUrl`).
- A6 Both adapters load the plugins only via dynamic `import()` (RecipeDetail is in the entry chunk). The `docs/native.md` entry check and the chunk-size limit must still pass.
- A7 The only `target="_blank"` link in src/ is the recipe source link (`RecipeDetail.tsx`). The "further links" bullet is a no-op.
- A8 The native project files regenerated by `cap:sync` (`android/capacitor.settings.gradle`, `android/app/capacitor.build.gradle`, `ios/App/CapApp-SPM/Package.swift`) are committed. `docs/architecture.md` §6a lists the new adapters. `docs/native.md` gets a section with check lines (cook mode + recipe page toggle; source link opens in-app browser, "back" returns to the recipe).
- A9 AC3: the real label is „Bildschirm anlassen“. In addition to the device check, a Vitest case (Capacitor stubbed, no `navigator.wakeLock`) checks that the toggle renders in cook mode.

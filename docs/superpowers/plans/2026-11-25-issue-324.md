## Schritt 3: `src/native/appShell.ts` + Test (Commit 3)
API (alles No-op ohne `isNative()`; Plugins nur per `import()`, `Style` aus dem dynamischen Modul, A1):
```ts
const SPLASH_FALLBACK_MS = 3000
export function startSplash(): void                   // Fallback-Timer; nur nativ; ein zweiter Aufruf plant nichts neu
export function hideSplash(): void                    // idempotent, Guard auf Modulebene, löscht Fallback-Timer
export function setStatusBarStyle(mode: 'light' | 'dark'): void  // dark → Style.Dark, light → Style.Light
```
- Ladefunktion `loadSplash`/`loadStatusBar` per `??=`-Cache wie `timerNotifications.ts`. Fehler werden wie in `backButton.ts` geloggt (`.catch((error: unknown) => console.error(error))`), nicht geworfen: Ein fehlendes Plugin darf die App nicht brechen (Review 2 #4).
- `hideSplash`: Der Guard wird sofort gesetzt (StrictMode-Doppelaufruf ruft `hide` nur einmal). Der Fallback-Timer wird erst gelöscht, wenn `SplashScreen.hide()` erfolgreich war. Scheitert der Aufruf, feuert der Fallback nach 3 s noch einmal `hide` (ein einziger Wiederholversuch). Im Kommentar steht das bewusst so (Review 2 #4).
- Statusleiste: `void loadStatusBar().then(({ StatusBar, Style }) => StatusBar.setStyle(...)).catch((error: unknown) => console.error(error))`. Keine eigene Queue: Beide Aufrufe warten auf dasselbe gecachte Promise, ihre `.then` laufen in Aufrufreihenfolge (Review 1 #10).
- Für Tests: Spies per `vi.hoisted` anlegen und aus den `vi.mock`-Factories zurückgeben. Vor jedem Test `vi.clearAllMocks()` (Aufrufzähler der geteilten Spies, wie `timerNotifications.test.ts`), `vi.resetModules()` und `appShell` neu importieren (frischer Guard, Ladecache) (Review 2 #2). `vi.stubGlobal('Capacitor', …)`, im `afterEach` `vi.unstubAllGlobals()`. Fake-Timer; asynchron warten mit `await vi.advanceTimersByTimeAsync(...)` und `await vi.dynamicImportSettled()` (Review 1 #4).
- Kopfkommentar im Stil der anderen Dateien.
- `src/native/appShell.test.ts` (Vitest, `vi.mock('@capacitor/splash-screen')`, `vi.mock('@capacitor/status-bar')` mit eigenem `Style`-Enum-Mock):
  - Web (kein `globalThis.Capacitor`): `startSplash`, `hideSplash`, `setStatusBarStyle('dark')` → keine Plugin-Funktion aufgerufen, auch nach `vi.advanceTimersByTime(3000)` (AK2a).
  - Nativ, Render scheitert: `startSplash()`, kein `hideSplash` → nach 2999 ms 0×, nach 3000 ms `SplashScreen.hide` 1× (Fake-Timer) (AK2b).
  - Nativ, Render ok: `startSplash()`, `hideSplash()` ×2 (StrictMode) → 1×; danach 3 s vorbei → weiterhin 1× (A5).
  - `setStatusBarStyle('dark')` → `setStyle({ style: Style.Dark })`; dann `'light'` → `Style.Light`, in dieser Reihenfolge (AK3).
  - `hideSplash()` vor `startSplash()` sowie ein zweiter `startSplash()` → kein zweites `hide`, auch nach 3 s (Review 1 #9).

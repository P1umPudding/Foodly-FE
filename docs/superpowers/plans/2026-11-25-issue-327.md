### 3. `auth.ts` native cache (commit 3)
- Imports: `isNative` from `../native/platform`, `loadAuth`, `saveAuth` from `../native/storage` (static; both
  modules have no static Capacitor import, A1).
- Split `readStored` into `parseStored(raw: string | null): StoredSession | null` (current validation) and
  `readStored()`: web → `parseStored(localStorage.getItem(KEY))` (unchanged try/catch); native → `nativeSession`
  (module variable, `null` until loaded).
- `writeStored(session): Promise<void>`: web → as today, returns `Promise.resolve()`. Native → set
  `nativeSession = session`, `written = true` (A6, one-line safety net with a short comment: a load finishing after a
  write must not overwrite it), on `null` also `localStorage.removeItem(KEY)` (so a kept legacy copy can't bring a
  signed-out session back), and return `saveAuth(session ? JSON.stringify(session) : null)
  .catch((error) => console.warn(...))` (A3: never rejects).
- `export async function loadSession(): Promise<void>` (A4/A5/A6): web → return. Native:
  - `raw = await Promise.race([loadAuth(), timeout(3000)])` in try/catch: a rejection or a hanging bridge
    (`main.tsx` renders only after `bootstrap()` settles, the splash fallback does not render) counts as a failed load.
  - load failed → stay signed out, touch nothing, warn, return (no notify needed: nothing changed).
  - If `written` meanwhile → return (a write before the load wins).
  - `stored = parseStored(raw)`; legacy = `localStorage.getItem(KEY)`.
  - `stored` → `nativeSession = stored`; remove legacy key.
  - else if `parseStored(legacy)` → `nativeSession = it`; `void saveAuth(raw).then(() => localStorage.removeItem(KEY),
    warn)` — not awaited, so a hanging bridge can't block `bootstrap()`; the queue orders it before any later write.
    On failure the legacy copy stays for the next start.
  - else → remove a corrupt legacy value. (A corrupt Preferences value just parses as null; the next write replaces it.)
  - The timeout timer is cleared in `finally`.
  - `notify()` at the end (index.ts listener updates `cachesFor`; `lastNotified` correct).
- Callers that must wait for the write (A3/A8):
  - `refreshLocked`: `await writeStored({ ...now, accessToken, refreshToken })`, then
    `return tokenOf(readStored(), sent.userId)` (a sign-out during the write still yields null). Covers proactive
    refresh and 401 retry, both go through `refresh()`. Only this caller (and the retry it triggers) waits; other
    requests may already use the new access token from memory — fine, rotation already happened; moving the cache
    update after the write would let a refresh resurrect a signed-out session. Said in the header and the PR.
  - `startSession`: `const write = writeStored(...)`; `if (replaced) void logout(replaced)`; `notify()`;
    `await write`; return (subscribers learn at once, the promise resolves after the write).
  - `signOut`: `endSession` returns the write promise; `signOut` returns `Promise.all([write, logout(current)])`
    mapped to void. Web: write resolves at once, so behaviour unchanged.
  - `endSession` (expiry paths) — the write is fire-and-forget via the returned promise with `void` (never rejects).
- `storage` event listener and `navigator.locks` unchanged (A7).
- Header comment: "Web: every access re-reads localStorage …; native: an in-memory copy loaded once in bootstrap()
  and written through to Preferences (iOS may clear WebView storage)". One sentence each, no wall.

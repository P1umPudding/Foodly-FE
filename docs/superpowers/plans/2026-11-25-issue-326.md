### 2. `src/native/keepAwake.ts` + `keepAwake.test.ts` (commit 2)
- Short header: why a plugin is needed (Android WebView and iOS < 18.4 lack the Wake Lock API; the native shell always
  uses the plugin, A2) and why there is a queue (A3).
- `loadPlugin = () => (plugin ??= import('@capacitor-community/keep-awake'))`.
- `queue` chain: `function run(op) { const p = queue.then(op); queue = p.catch(() => {}); return p }`. The caller gets
  the rejection; the stored chain swallows it so one failure doesn't block later calls.
- Header also states the single-holder assumption: the plugin is global and doesn't count callers, so one
  `allowSleep` releases every holder. Safe today (RecipeDetail and CookMode are separate routes; the old cleanup runs
  before the next `keepAwake`), a second simultaneous caller would need a counter. No comments on the small functions.
- `export function keepAwake(): Promise<void>` → `run(async () => (await loadPlugin()).KeepAwake.keepAwake())`.
- `export function allowSleep(): Promise<void>` → same with `allowSleep()`.
- These are only called on native; the hook decides, and the adapter does no `isNative()` check of its own.
- Tests (`vi.mock('@capacitor-community/keep-awake')`, `vi.resetModules()` + dynamic import as in
  `timerNotifications.test.ts`):
  - `keepAwake` then `allowSleep` call the plugin in that order, even when `keepAwake` is still pending (the deferred
    plugin promise is resolved only after `allowSleep` was queued) → `allowSleep` runs after `keepAwake` settles.
  - A rejecting `keepAwake` rejects the returned promise, and a later `allowSleep` still runs.

### 3. `useWakeLock` native path (commit 3)
- `const native = isNative()`; `supported = native || (typeof navigator !== 'undefined' && 'wakeLock' in navigator)`.
- In the effect, when `native`: `let cancelled = false`;
  `keepAwake().catch(() => { if (!cancelled) setEnabled(false) })`; cleanup: `cancelled = true;
  allowSleep().catch(() => {})`. Return before the web branch: no `visibilitychange` listener natively (A3).
- Effect deps become `[enabled, supported, native]` (`react-hooks/exhaustive-deps`).
- StrictMode: keepAwake → allowSleep → keepAwake, kept in order by the queue; `cancelled` stops the first run from
  switching the toggle off.
- The web branch stays byte-identical.
- Header comment: one extra sentence on the native path.
- Tests in `src/hooks/useWakeLock.test.ts`, new `describe('native')` with `vi.mock('../native/keepAwake')` (`keepAwake`,
  `allowSleep` as `vi.fn`) and `vi.stubGlobal('Capacitor', { isNativePlatform: () => true, getPlatform: () => 'android' })`.
  `afterEach`: `vi.unstubAllGlobals()`. The mock applies to the whole file, but the web tests never reach the adapter
  because `isNative()` is false there. AC1:
  - `supported` is true without `navigator.wakeLock`.
  - `useWakeLock(true)` → `keepAwake` once; `setEnabled(false)` → `allowSleep` once.
  - Unmount while enabled → `allowSleep`.
  - `keepAwake` rejecting → `enabled` becomes false.
  - Visibility events trigger no further `keepAwake`.
  - Existing web tests unchanged and green.

- `RecipeDetail.tsx` source link: keep `href`, `target`, `rel`; add
  `onClick={isNative() ? (e) => { e.preventDefault(); openExternal(recipe.source) } : undefined}`.

  imported modules without static Capacitor imports (A6).
- `src/native/openExternal.test.ts`: `Browser.open` is called with `{ url }`; a rejection is swallowed (no unhandled
  rejection).
- AC2 test: new `src/pages/RecipeDetail.source.test.tsx` (setup copied from an existing small RecipeDetail test, mock
  path). It mocks `../native/openExternal`.
  - Native (Capacitor stubbed): click the link → `openExternal` called with the URL; the click event's
    `defaultPrevented` is true (`fireEvent.click` returns false).
  - Web: not called and not prevented; the link has `target="_blank"`. To avoid jsdom's "Not implemented: navigation"
    noise, a `document` click listener calls `preventDefault` itself after reading `defaultPrevented === false`.
  - Needs a mock recipe with a URL source. Check `src/mocks/data`; otherwise override that recipe's `source` in the test.
- grep: only `target="_blank"` in src/ is this link (A7). Nothing else to touch.

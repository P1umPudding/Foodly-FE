# Spec (Dispatcher)

## Context
Listensuche legt pro Tastendruck einen Verlaufseintrag an (Zurück geht buchstabenweise) — siehe Originalmeldung oben.

## Goal
Tippen in die Listensuche erzeugt keine History-Einträge pro Buchstabe.

## Behaviour
Während des Tippens wird der Sucheintrag im Verlauf ersetzt (`replace`). Ein Zurück nach dem Tippen führt zum Zustand vor der Suche bzw. verlässt die Liste. Andere Filter-/Sortieränderungen (Chips, Sortierung) verhalten sich wie bisher.

## Acceptance criteria
1. „pasta“ tippen und einmal Zurück → nicht „past“, sondern der Zustand vor der Suche.
2. Suchänderungen nutzen `setParams(..., { replace: true })` (oder Debounce + ein Eintrag); Filter-/Sortierwechsel bleiben eigene Einträge.
3. Persistenz des Listenzustands (savePersisted) funktioniert unverändert.
4. Test für das Replace-Verhalten bei Suche.

## Non-goals
Keine Änderung an Filter-/Sortier-History, kein neues Suchverhalten (Treffer, Debounce der Anfrage optional).

## Assumptions
Nur die Suche ersetzt; Filterwechsel bleiben navigierbar.

## Affected areas
`src/list/useListState.ts` (set: Option replace), `src/components/list/SearchInput.tsx`, Tests.
